# Kinetix production studio roadmap

## Product direction

Kinetix should let an illustrator draw a faceted character from a blank artboard, hand it to a rigger, animate it in several shots, review a proposed change from an AI editor, and deliver both editable artwork and rendered animation. A motion designer should be able to use the same document, layers, and timeline to animate a wordmark without creating a skeleton.

The 23 subgoals in M5–M9 cover three production workflows. A creator can start from an empty project, use their own drawings or imported assets, choose a delivery target, and make a revision after the first delivery. An authorized MCP agent can complete the same workflows without someone operating the editor. Each workflow earns release status after the editable source is reopened and the deliverable plays in its intended destination.

| Production workflow | What the studio must let the creator do | Finished delivery |
| --- | --- | --- |
| Frame-by-frame or pixel animation | Sketch, ink or pixel-paint, organize layers and palettes, draw and reuse cels, time exposures, preview loops and revise the artwork. | Transparent PNG frames or a fixed-grid or packed sprite atlas with timing, origins and named animations. |
| Rigged 2D character for a game | Draw or import a character, rig and skin it, swap expressions and props, animate directional clips and transitions, and author events, sockets, collision geometry and root motion. | A baked sprite bundle and a runtime rig where the target supports it. Verify both in a controlled playable scene and reimport a revision without replacing scene references. |
| Short film or motion graphics | Board and time shots, mix vectors, cels, rigs and text, choreograph cameras and effects, sync sound, review takes and approve a master. | A portable editable project, a rendered master, and the requested vector, alpha or audio deliverables. |

### Verified starting point

Blank custom artboards, precision paths, shared polygon facets, nested layers and vector appearance are deployed alongside indexed and RGBA cels, basic rigging, mesh weights, clip editing and scoped MCP. Studio and MCP import layered SVG artwork into editable paths. Version 2 bundles export multiple clips as loose PNGs, fixed grids or packed atlas pages. The browser player and the Godot 4.5.1 adapter verify placement and timing across all three layouts. Godot also verifies reimport across a clip rename and retains version 1 fixed-grid playback. Hosted Inngest rendering still needs verification after the production keys are present. See [implementation progress](../PROGRESS.md) and the [sprite export contract](ENGINE_EXPORT.md).

## Human and agent tool coverage

Ship the UI action and its MCP equivalent in the same authoring subgoal. Both call the same validated document commands under the caller’s project permissions. Test the same storyboard twice, once from the UI and once from a fresh MCP session. Compare the resulting geometry, pose samples, clip timing, event tracks and rendered frames. The agent must be able to inspect its work visually as well as read document state.

The agent starts by discovering available capabilities and target versions for its project. It can open a blank document within its granted scope, inspect existing work, make a revision-checked batch, render the result, correct it, and export the approved revision without a human operating the UI. Approval remains a named role for projects that require it. Use the same permissions for reads, edits, previews and downloads. Destructive changes and large bakes can be previewed before applying them.

| Workflow | Artist interaction | Agent capability and evidence |
| --- | --- | --- |
| Inspect and plan | Browse artboards, layers, assets, shots and keys. Isolate a layer and inspect a frame. | Discover supported operations and limits. Query objects by name or stable ID, read evaluated transforms and timelines, and request scoped frame images, transparent layer renders, skeleton or bounds overlays and contact sheets. |
| Create and revise | Draw polygons, brush strokes or cels. Edit styles, text, layer order and topology. Import authorized project assets. | Submit geometry, stroke samples, cel edits, text, materials and asset references in validated batches. Preview affected bounds and a rendered diff. Replaying a retried batch must create each object only once. Report unsupported inputs with the affected object and error location. |
| Rig and animate | Bind a mesh, paint influences, pose limbs, key channels, time dialogue, edit cuts and preview a loop. | Inspect weights and pose errors, change bindings and keys, edit shots and cues, sample a frame range, and compare the first and last loop poses. Expose explicit time units and coordinate spaces. |
| Direct and review | Author a take, see another editor’s changes, approve a revision or restore it. | Work against a named revision, create a take, report a conflicting object, and apply or undo the accepted batch. Review and approval follow the same role rules as the UI. |
| Deliver and diagnose | Select a target, preflight it, preview baked features, export, and retrieve the package. | List profiles, validate an approved revision, render target-profile previews, choose bake options, export, poll or cancel, retrieve scoped artifacts and read structured import diagnostics. A worker retry preserves the original snapshot. |

### Agent authoring session

1. Discover project permissions, available operations, supported file types, render limits and export profiles. Open or create a document within the granted workspace. Inspect only the referenced assets, layers, channel ranges or revisions, with pagination for large projects.
2. Save a revision-checked edit batch for each logical step. Accept editable inputs such as vector coordinates, Bézier handles, brush samples with pressure, cel references, bone weights and key tangents. Return created IDs, changed tracks and structured validation errors. Dry runs use the same validation as commits.
3. Request a rendered frame, a selected layer, an overlay of rig controls and hitboxes, a contact sheet or a private playback artifact. Return resolution, timebase, frame range and source revision with the result, so an agent can compare silhouettes, contacts, easing and timing against its intent.
4. Compare takes from an identical frame range, apply the chosen revision with attribution and test edit recovery by retrying a request or reconnecting. An export preflight identifies which effects, attachments or gameplay data require baking, sidecars or a different profile.
5. Export and fetch the revision-pinned artifacts. Re-run the preflight after a revision and read the importer report. A supported headless receiver can run the native certification fixture and return usable paths and diagnostics. The agent’s project credentials authorize Kinetix operations. Engine project installation and updates run in the recipient’s environment.

Show expected files, dimensions, estimated texture memory, and which features travel as runtime data, baked frames or companion files. Users of an unlisted engine get a portable package, a documented loader contract and a reference player. Publish support by combination of engine version, package or plugin version, profile and feature. Use **verified native** for a tested importer, **portable** when the engine can consume the documented frames and metadata through a loader, and **planned** for an untested integration. Compatibility with a third-party runtime format such as Spine requires a separate profile with version, licensing and fidelity checks.

### Import experience and version upgrades

- In a verified engine, install the documented editor plugin or run the provided import command, choose the ZIP, then drop the generated prefab or scene into a level and select a clip. Include a starter scene with idle, walk, jump, animation direction, a prop socket and an event-driven effect where the profile supports them.
- At import, show the profile and schema, clip names and directions, generated assets, target units, and which features are native, baked, companion data or unavailable. Give the asset path and repair action when the profile, dependency or transform is unsupported. Keep the importer and starter assets versioned with documented installation and upgrade steps.
- On reimport, match stable source IDs across clip renames, atlas repacking and texture scale changes. Keep game-owned controller logic, placement, scene references, overrides and event bindings. Preview generated creations, changes and removals. A partial export can leave an existing omitted clip available, with the omission listed in the report. Apply only a validated change set and preserve the previous playable assets when validation fails.
- For an engine with a basic image slicer, offer a no-rotation full-frame grid, the cell dimensions and frame order, and a constant-rate option that expands variable holds. A documented JSON companion preserves timing, pivots, events, collisions and sockets for destinations that can read it. Include a minimal reference loader and fixture to test a custom adapter.

### Portable bundle contract

- Use a documented manifest version and schema with stable asset, clip, frame and attachment IDs. Include the approved source revision, profile, exporter and adapter versions, package file checksums and the complete list of baked or companion features.
- Define coordinates from a top-left source origin, pivots relative to the original frame, and an explicit integer timebase with frame durations and event ticks. Record coordinate and unit conversions in the importer receipt. Use defined loop boundaries so held frames and loop events play consistently across engines.
- Carry alpha mode, color space, filtering, actual texture size, trim offsets and bounds. Declare attachment sockets, hitboxes, root motion and custom events as structured sidecar data whenever the target profile cannot map them natively.
- Show a target-profile preview and actionable preflight. For example, name the affected layer when a blur is baked, identify which pivot will shift if a simple slicer ignores its metadata, and show estimated atlas pages and memory. Export only the selected revision and report exactly which files were produced.
- Validate the import in a clean project, then reimport with an updated pivot, renamed clip and repacked pages. Preserve game-owned scene references and settings. Cover unavailable dependencies, old and unsupported schema versions, repeat imports and rejection of malformed packages before project files are updated.

## Workspace and shortcuts

Use a single studio with **Design**, **Rig** and **Animate** workspaces. Keep the canvas, document and selection stable when switching. The left panel shows layers, bones or animated channels according to the active workspace. The right inspector shows properties for the selected object, face, bone or key. The timeline can collapse during drawing and expand for curves and audio. Keep presence in the header and place tool-specific options beside the floating toolbar.

Add a searchable command palette, discoverable and remappable shortcuts, numeric alternatives to dragging, visible focus, touch-friendly handles and a reduced-motion preference for interface transitions. Drawing and weight brushes should support pen pressure. At phone widths expose the canvas, active tool and timeline transport immediately, with a drawer for properties. Keep desktop, tablet, portrait phone and landscape phone in the viewport test matrix.

## Engineering and release gates

- **Document compatibility.** Give artboards, layers, faces, assets and compositions stable IDs and explicit coordinate spaces. Store source geometry, deformation data and animation tracks separately. Build fixtures for each saved document version. Test the same source in the viewport, worker and exports.
- **Safe editing and recovery.** Group a drag, brush stroke or agent proposal into one undoable command. Add local draft recovery and named server revisions. Test a closed tab during a save, two editors changing the same object, and reconnection after edits on different objects. A restored draft must identify the server revision it was based on.
- **Performance.** Establish a reference device and fixture before promising capacity. An initial desktop target is 60 fps playback at 1080p for one character with 100 bones and 5,000 mesh vertices across its parts. Record frame-time percentiles and scrub latency. Benchmark hit testing, deformation and rendering independently before moving a bottleneck to WebGL2 or a worker. Publish a separate mobile benchmark.
- **Export fidelity.** Maintain reference scenes for a cutout logo, skinned character, title with audio, and transparent sprite. Compare sampled frames and bounds between preview and each supported renderer. Evaluate vector exports in an independent viewer. Move large render artifacts into object storage and establish measured duration and resolution limits before raising existing caps.
- **Collaboration and access.** Validate document scope and permissions for every human, reviewer and agent command. Test revoked access, duplicate delivery and stale revisions. Keep named versions and immutable render inputs available for replay.
- **Human and agent parity.** A feature is ready when it has a discoverable editor action, a documented MCP operation, shared validation and a parity fixture. Compare semantic outputs such as timing, frame pixels and bindings. Allow different asset IDs across independent runs while checking that IDs stay stable through revisions of each project.
- **Importer certification.** Record exact tool versions and archive import reports. Check frame durations and event counts, pivot placement, socket transforms, alpha and filtering on sprites, and deformation tolerances on rigs. Carry approved fixture packages forward so exporter and adapter updates exercise backward compatibility.
- **Release discipline.** Use BRIEF → BUILD → TEST → MERGE → DEPLOY → DOCUMENT for each subgoal. Pair Vitest checks for geometry, commands and persistence with Playwright checks for the artist workflow. Verify an authenticated hosted workflow before updating the progress, architecture and handoff documents.

## Release order

1. **First playable asset · verified.** Basic artboards and timing from 5.1 and 7.1, a fixed-grid profile from 9.1, and a Godot 4.5.1 adapter from 9.3. The revision-bound preflight and repeat import are the baseline for later profiles.
2. **Illustration and sprite production · active.** The layered badge, drawn cels, version 2 portable layouts, Godot multi-clip import and editable SVG import are verified. Start with PNG sequence import before certifying Unity and web sprite profiles.
3. **Runtime characters.** Finish M6 and expanded clip authoring from 7.1, ship named shared-rig versions, and connect the 7.6 player to the 9.2 runtime contract. Certify sprite and runtime profiles independently with the playable character fixture.
4. **Full animation production.** Finish M7 and M8. Connect storyboards, dialogue, compositing and take review to approved master delivery. Verify hosted rendering, audio sync, alpha and portable project recovery.
5. **Broader engine coverage.** Finish 9.3 and 9.4 with Unreal and GameMaker sprite importers, a custom-engine conformance kit, certified version ranges and automated reimport fixtures. Publish the versioned coverage matrix with each release.

## End-to-end production fixtures

Run each fixture from a blank project through both the studio and MCP. Each run produces an editable source archive and the listed deliveries, with a receipt bound to its source revision. Certification fixtures should include an edit after the first export so the test exercises a real production revision.

| Fixture | End-to-end test |
| --- | --- |
| Pixel flame | Draw six cels with unequal holds, an intentionally blank frame and an asymmetric silhouette. Deliver individual PNGs, a fixed sheet and a packed atlas at 1× and 3×. Compare the named loop and anchor position in the reference player and each certified sprite importer. |
| Playable fox | Draw and skin a faceted fox with a weighted elbow, planted foot and swappable lantern. Author idle, walk and jump, a lantern socket, two footfalls per walk loop and collision frames. Play sprite and compatible runtime versions in clean engine projects. Verify that direction changes, one-shot jump and return to idle work through player input. Revise the pivot, rename a clip and repack the textures. Reimport twice and verify scene references, overrides, socket positions and event counts. |
| Finished sequence | Board a ten-second fox scene with a camera move, sound cues, dialogue and one reviewed agent edit. Deliver the master, a transparent shot sequence and WAV stems. Also animate a wordmark using paths and type to exercise a vector-only delivery. Compare selected frames, audio sync, missing-asset behavior and restoration of the approved source. |

Automated comparisons check exact integer frame durations, loop boundaries and event counts. Record expected transforms in source-pixel coordinates and compare them after the importer’s unit conversion. Set explicit per-profile tolerances for sampled geometry, filtering and lossy media and record actual errors in the certification report. Archive the input package, exact exporter and importer versions, playback or render evidence, and the results of reimporting an updated and an unchanged package.
